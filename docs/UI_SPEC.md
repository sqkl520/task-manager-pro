# UI 复刻说明

本项目的界面是**依据 Windows 10 任务管理器的可观测规格从零实现**的，没有复制任何源代码。
规格来源有两类：

1. **本机 MUI 资源解析** —— `C:\Windows\System32\zh-CN\taskmgr.exe.mui` 的 STRINGTABLE，
   逐条提取出 848 条字符串，作为文案的权威依据（见 `docs/specs/ui_spec.md`）。
2. **本机行为实测** —— 进程分组规则、挂起判定、各列数值来源，全部在目标机上验证过
   （见 `docs/specs/proc_semantics.md`）。

## 关键设计决策（为什么不照抄原版）

### 1. 不复制源代码

原版是 **DirectUI**（`DUI70.dll` + `DUser.dll`）自绘，闭源。本项目是**独立的 Win32 + GDI 自绘实现**，所有绘制逻辑、布局计算、数据结构都是自己写的。参考的只有"可观测的视觉结果"和"可测量的行为规格"。

### 2. 架构层面刻意不模仿原版

原版把采集压在单线程、无背压、每秒全表重算，这是它卡死的根源。本项目：

- 采集在独立线程，UI 只读不可变快照（`shared_ptr` 零拷贝发布）
- 滚动时用后备缓冲内 `BitBlt` 搬移，只重画新暴露的条带
- 稳态 CPU 占全系统 **0.12–0.29%**，原版是 6.4%

**UI 像素层面模仿，架构层面绝不模仿。**

### 3. 热力图用开方压缩

原版按"值 / 列最大值"线性归一化。但本机 CPU 分布极不均衡（最大 90%、其余多为 0.x%），
纯线性会让绝大多数行接近纯白。实测原版在 0.9% 的进程上也有明确淡蓝，
因此对归一化结果做开方压缩，视觉层次更接近原版。

### 4. 图标用后台线程 + 缓存

`SHGetFileInfo` 实测 6.1ms/次、最大 144ms，450 个进程 = 2.7 秒。
绝不能放在绘制路径。做法：低优先级后台线程 + 有界队列（700）+ 持久缓存，
绘制路径只查哈希表。启动初期先显示首字母色块，几秒内自动换成真实图标。
