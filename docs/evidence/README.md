# 取证资料

这个目录存放实现过程中从本机实测得到的一手数据：Windows 10 任务管理器
的 UI 布局反推、MUI 字符串提取、系统指标采样、性能链路基准。

源码注释里引用这些文件作为数值的来源依据。凡是写「实测」「确证」的地方，
都能在这里找到对应的原始数据。

## 为什么只有一部分文件在这里

| 保留 | 不保留 |
|---|---|
| 可读的文本转储（`.md` `.txt` `.tsv` `.json` `.xml`） | 截图与裁切图（`.png` `.bmp`） |
| 用来取数的探针源码（`.cpp` `.ps1` `.js`） | 探针编译产物（`.exe`） |
| 单文件小于 2 MB 的 | 超过 2 MB 的单个转储 |

**截图不进仓库**的原因不是保密，是体积：原版任务管理器的参考截图与放大裁切
合计数百 MB，且每次比对都会重新生成。它们留在开发机的工作区里。

**超过 2 MB 的单独大文件**同样只是体积问题。最大的一个是 `tm/disasm.txt`
（17.8 MB 的反汇编转储），它本身还是编码损坏的，没有阅读价值，因此不收录。

代码注释里如果引用了一个不在这里的文件，说明它是上述两类产物之一。
这类引用保留原意——它记录的是「这个数值是哪次测量得出的」，
而不是「点这里可以打开」。

## 可信度标注

原始文档里用三档标注每个结论的可靠程度：

| 标注 | 含义 |
|---|---|
| **[确证]** | 本机实测，或权威文档直接写明 |
| **[强推测]** | 从多组实测数据反推，逻辑闭合，但未直接观测到 |
| **[推测]** | 从行为观察归纳，未获一手证据 |

引用这些结论时请连同标注一起引用。把一个 `[推测]` 当成 `[确证]` 用，
是这个项目历史上反复出现过的一类错误。

## 复现

测量都是在 Windows 10 Pro 22H2 (22H2) / Xeon 服务器级 CPU (10C/20T) /
32 GB 上做的。换机器数值会变，但**量级关系**（哪条链路便宜、哪条是灾难）
是这个项目的核心结论，不随机器改变。

## 关于这里的探针源码

`docs/evidence/` 下的 `.cpp` 与 `.ps1` 是**取证时的原始存档**，不是现在还能
直接跑的工具。两点注意：

- **路径**：原始版本里写的是开发机上的绝对路径。多数已改成相对脚本自身定位，
  少数保留原样并在文件头注明——那是「当时在哪跑的」的记录
- **可编译性**：一部分探针依赖当年的 Windows SDK 版本，现在用新 SDK 会编译
  失败（例如 `gpuinfo_probe14.cpp` 依赖的 `d3dkmthk.h` 结构已变）。
  它们记录的是**那次测量怎么做的**，不是「现在跑跑看」

要重新测量，请照存档里的做法重写一个探针，而不是直接编译这些文件。
