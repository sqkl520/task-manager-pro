   （y=675 起直接是黑框），而 `p_services.png` 有完整工具条 + 状态栏。

### 1-4 服务页列头文字色 `#5A5A5A` 偏浅，原版与数据行同深（明显）

### 5-8 四页右键菜单的「有选中项」判定用错了变量（严重）

**问题**：`src/tmwindow_events.cpp:515-527`
```cpp
int r = HitTestRow(y);                       // ← 只查进程页的 rows_
if (r >= 0) { selectedRow_ = r; ... }
bool hasSel = (selectedRow_ >= 0 && selectedRow_ < (int)rows_.size());
...
case TabId::Services:
    popup = MenuBuilder::BuildServiceContext(hasSel, hasPid);   // ← 用的是 hasSel
    break;
case TabId::Users:
    popup = MenuBuilder::BuildUserContext(hasSel, expanded);    // ← 同上
    break;
case TabId::AppHistory:
    popup = MenuBuilder::BuildAppHistoryContext(hasSel);        // ← 同上
case TabId::Startup:
    popup = MenuBuilder::BuildStartupContext(hasSel, true);     // ← 同上
```

`hasSel` 完全来自**进程页的 `rows_` / `selectedRow_`**，
与 `pagesView_.SelectedService()` / `SelectedUser()` / `SelectedStartup()` **毫无关系**。

后果：
1. 在服务页选中一行后右键 → `hasSel` 仍取进程页的状态。
   如果进程页从未选过任何行（`selectedRow_ == -1`），`hasSel = false`
   → 服务页的「开始/停止/重新启动」全部**置灰**
2. 反过来，如果进程页选过一行，`hasSel = true`，
   而 `hasPid` 又正确取了 `SelectedService()` —— 于是可能出现
   **菜单显示"可停止"但实际没有选中任何服务**（`StartService(-1)` 返回 false）

另外 `case TabId::Startup` 传的第二个参数是**硬编码 `true`**
（"是否启用"），完全不看选中的那一项实际是启用还是禁用 →
启动页右键永远只显示「禁用(&D)」，选中的是已禁用项时也不会变成「启用(&E)」。

**对照 MUI**：`Startup Item Context` 是 `启用(&N)` / `禁用(&A)`
（`_probe/tm/menus_dump.txt`；注意助记符是 `&N`/`&A`，与这段代码 `启用(&N)`/`禁用(&A)` 一致），
两者应互斥显示。

**差多少**：
- 服务页/用户页/启动页/应用历史页的右键菜单**可用性判定全部错**
- 启动页永远只给一个方向的菜单项
- 服务页可能出现"菜单说能停，实际没选中"

**严重度：严重**（右键菜单是原版这几页的主要操作入口）
