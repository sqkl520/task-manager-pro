# 文档总览

Task Manager Pro 的文档分四块。按你来的目的选一块。

## 我想知道这东西为什么值得做

| 文档 | 内容 |
|---|---|
| [DIAGNOSIS.md](DIAGNOSIS.md) | 原版任务管理器为什么在核多、线程多的机器上卡死。含各条数据链路的实测耗时 |
| [BENCHMARK_RESULTS.md](BENCHMARK_RESULTS.md) | 两个实现的实测对比：无响应时长、CPU、内存、线程数、快照耗时 |

读完这两份就知道问题在哪、为什么换个实现能解决。

## 我想知道它是怎么做出来的

| 文档 | 内容 |
|---|---|
| [TECH_STACK.md](TECH_STACK.md) | 技术选型：为什么是 C++ / Win32 / Direct2D 而不是别的 |
| [UI_SPEC.md](UI_SPEC.md) | 界面从哪些可观测规格反推出来的，以及「没有复制源代码」具体指什么 |

## 我要改代码

| 文档 | 内容 |
|---|---|
| [specs/](specs/) | 逐模块的实现规格：进程分类规则、菜单文案、各页布局、性能页几何 |
| [evidence/](evidence/) | 上面那些规格的一手数据来源：MUI 提取、UIFILE 反编译、像素测量、链路基准 |
| [reference/](reference/) | 原版任务管理器的参考截图，供像素级比对 |

`specs/` 里的结论都带可信度标注（**[确证]** / **[强推测]** / **[推测]**），
`evidence/` 里能找到对应的原始数据。改代码前先看标注——把 `[推测]` 当
`[确证]` 用是这个项目历史上反复犯的错。

## 术语

| 词 | 含义 |
|---|---|
| **rp** | DirectUI 的布局单位，`1rp = dpi/96` 像素。本机 100% DPI 下等于 px |
| **UIFILE 30001 / 30024** | 任务管理器资源里的声明式布局文件，反编译后可读出每个元素的确切几何 |
| **duib** | `UIFILE` 编译后的二进制形态 |
| **组 / 分组** | 进程页的「应用 / 后台进程 / Windows 进程」三段。数值列排序时分组头会被抑制 |
