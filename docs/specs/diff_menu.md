## 差异清单

### A. 列头右键菜单 —— 整体没接（最严重）
- 菜单名：进程页/详细信息页 列头右键
- 原版：`30201 Header Context` = 隐藏列(&D) / 选择列(&S)；另有 `30216 Additional ColHeader Context`
  = 资源值三项（内存(M)/磁盘(I)/网络(N) → 百分比/值）。截图 `crops/hdr_menu_5x.png` 显示真实行为是
  「一列可勾选的列名清单：类型✓ 状态✓ 发布者 PID 进程名称 命令行 CPU✓ 内存✓ 磁盘 网络 GPU
  GPU 引擎 电源使用情况 电源使用情况趋势 + 底部 资源值(V) 子菜单」，`crops/hdr_submenus_5x.png`
  显示 内存(M) →〔百分比 / ●值〕（单选圆点在「值」上）。
- 重实现：`src/menus.cpp:254 BuildHeaderContext()` 只造了 2 项，且**全工程无任何调用点**
  （`grep -rn BuildHeaderContext src/` 只命中 menus.cpp 定义与 include/menus.h 声明）。
  `src/tmwindow_events.cpp:396 WM_RBUTTONUP` 不判断 y 是否落在列头区，一律走行菜单。
- 后果：在列头上右键弹出的是「进程页行右键菜单」或「详细信息行右键菜单」（含 结束任务），
  原版是列选择菜单。CMD_HIDE_COLUMN / CMD_SELECT_COLUMNS 也没有 `case` 处理（无实现）。
- 证据：menus_dump.txt 30201/30216；menus.cpp:254-259；tmwindow_events.cpp:396-458；
  `docs/evidence/README.md`、`docs/evidence/README.md`、`docs/evidence/README.md`

### B. 进程页右键（30208 Process Context）
原版顺序（menus_dump.txt:107-133）：
展开(P) / 折叠(P) / 切换到(T) / 重新启动(R) / **结束任务(E)** / 资源值(V) / 提供反馈(B) / ─── /
调试(D) / 创建转储文件(C) / 运行新任务(N) / 置于顶层(A) / ─── / 转到详细信息(G) /
打开文件所在的位置(O) / 在线搜索(S) / 属性(I)

1. 【多项 + 顺序】`结束任务(&E)` 位置错：原版在第 5 位（重新启动之后、资源值之前），
   重实现放到**最末尾**并单独加分隔线（menus.cpp:145-146）。用户最直观的「结束任务」被挪到最后。
2. 【缺项】`资源值(&V)` 少了两级：原版是 资源值 ▸ 内存(&M) ▸〔百分比 / 值〕、磁盘(&K) ▸〔百分比 / 值〕、
   网络(&N) ▸〔百分比 / 值〕；重实现只有 资源值 ▸〔百分比 / 值〕（menus.cpp:128-131）。
   注意原版进程页这里是 `磁盘(&K)`，而列头菜单 30216 是 `磁盘(&I)`。
3. 【缺项】`展开(&P)` 与 `折叠(&P)` 原版**同时存在**（两项都在，按状态置灰其一），
   重实现按 hasChildren/expanded **只生成一个**（menus.cpp:117-120）。
4. 【分隔线】多出 3 条：重新启动之后（menus.cpp:125）、资源值之后（menus.cpp:133）、属性之前（menus.cpp:143）。
   原版只有两处：提供反馈之后、置于顶层之后。
5. 【勾选】资源值子项原版是单选圆点 ●（hdr_submenus_5x.png 证实），重实现两个子项都没有任何标记，
   也没有状态变量（menus.cpp:129-130 region）。

### C. 详细信息页右键（30200 CPU Context）
原版：结束任务(E) / 结束进程树(T) / 提供反馈(B) / ─── / 设置优先级(P)▸ / 设置相关性(F) / ─── /
分析等待链(A) / 调试(D) / UAC 虚拟化(V) / 创建转储文件(C) / ─── / 打开文件所在的位置(O) /
在线搜索(N) / 属性(R) / 转到服务(S)

1. 【分隔线】多一条：结束进程树 与 提供反馈 之间（menus.cpp:156），原版没有。
2. 【分隔线】缺一条：`分析等待链(&A)` 之前原版有分隔线（dump 第 6 项），重实现没有（menus.cpp:169 紧跟 设置相关性）。
3. 【分隔线】多一条：`转到服务(&S)` 之前（menus.cpp:177），原版没有。
4. 【勾选】`设置优先级(&P)` 子菜单原版会对当前优先级画单选圆点，重实现 6 项全部无标记、不读当前优先级
   （menus.cpp:159-166）。（圆点这一点是按 Win10 行为推断，**未证实**到资源级。）

### D. 服务页右键（30202 Service Context）
1. 【分隔线】多一条：`转到详细信息(&D)` 之前（menus.cpp:191）。校验：`crops/svc_menu_6x.png`
   逐项为 开始(S)〔灰〕/ 停止(T) / 重新启动(R) / ─── / 打开服务(V) / 在线搜索(O) / 转到详细信息(D)，
   分隔线只在第 3、4 项之间。
2. 【未证实/缺项】原版另有 `30210 Service Context` = 停止(S) / 打开服务(O) / 在线搜索(S)（3 项、无「开始」
   也无「重新启动」），重实现没有这个变体。
3. 【置灰】`crops/svc_menu_6x.png` 里 开始(S) 在服务已运行时是灰的 —— 即置灰是按「服务当前状态」逐项判定；
   重实现只有一个 `hasSelection` 总开关（menus.cpp:184-192），不会因「已运行/已停止」分别置灰 开始/停止。

### E. 用户页右键（30211 User Context）

2. 【分隔线-顺序】重实现把分隔线放在 展开/折叠 之后（menus.cpp:201）和 切换用户账户 之前（menus.cpp:206）；
   原版唯一分隔线在 `切换用户账户(&W)` 与 `管理用户账户(&M)` 之间。
3. 【功能】`连接(&C)`（CMD_USR_CONNECT）**没有任何 case 处理**（tmwindow_menus.cpp 无此分支），点了无反应。
   `断开连接(&D)`/`注销(&I)` 有处理。

### I. 主菜单栏（30205）
原版 文件(&F)：`运行新任务(&N)` / `退出(&X)`  —— **两项之间无分隔线、无省略号**

   选「详细信息」→ 跳到「服务」页；选「服务」(idx=6) → 越过 TabId::Count，属于越界枚举值。
6. 【置灰逻辑 Bug】`按类型分组(&G)` 的置灰条件 `currentTab == 0 || currentTab == 5`
   （menus.cpp:93）—— 5 是 TabId::Count，详细信息页其实是 3，所以在**详细信息页该项被误置灰**。
   证据：include/tabs.h 枚举定义 + menus.cpp:93。
