# Windows 10 任务管理器 —— 性能页完整还原规格

> 目标机：Windows 10 Pro 22H2 22H2 / Xeon 服务器级 CPU (10C/20T, 恒定 3001 MHz) / 32GB
> 本文档所有标注【实测】的数值，均由 `tools/perfsrc.cpp`、`tools/memprobe.cpp`、
> `tools/wildtest.cpp`、`tools/perfcost.cpp` 在本机直接测得，原始输出见
> `docs/evidence/perfsrc_out.txt`、`docs/evidence/memprobe_out.txt`、`docs/evidence/wildtest_out.txt`、
> `docs/evidence/perfcost_out2.txt`。
> 文案来源：【实测-MUI】= 从 `C:\Windows\System32\zh-CN\taskmgr.exe.mui` 的
> STRINGTABLE / MENU 资源直接解析（848 条字符串 + 16 个菜单）。

## 0. 一句话结论（给实现者的最短路径）

性能页全部数据源在一台 20 核机器上的合计成本约 **5.6 ms/次**，占 1 Hz 刷新预算的
**0.56%**，其中最大的两项是网络（2.2 ms）和 GPU（1.4 ms）。**不需要任何 ETW、
不需要 WMI**，用 `NtQuerySystemInformation` + PDH 就够。唯一的禁区是
`\Process(*)\IO Read Bytes/sec`（18.8 ms，533 实例），进程页的磁盘列不该每帧拉。

### 1.1 与当前实现的差异（必须改）

当前代码用的是**左侧竖直导航栏**（7 项竖排），那是 **Windows 11** 的布局。

**Win10 是顶部横向选项卡。** 铁证来自 MUI 的 MENU 30205：

```
选项(&O) → 设置默认选项卡(&D) → 进程(&R) / 性能(&E) / 应用历史记录(&I) /
                                启动(&T) / 用户(&U) / 详细信息(&L) / 服务(&V)
```

"**选项卡**" = Tab。左侧导航栏不会叫"选项卡"。

## 8. 数据源方案（本机实测，最重要）

### 8.1 总表

| 数据项 | 数据源 | 实测成本 | 实例数 | 结论 |
|---|---|---|---|---|
| **每核 CPU 时间** | `NtQSI(8)` 一次拿全部 | **0.073–0.116 ms** | 20 | ✅ **首选，一次调用拿 20 核** |
| CPU 总利用率 | 由 class 8 自己算 | **0** | — | ✅ 不要用 PDH |
| PDH `\Processor(*)` | collect+read | 0.51 ms (p95 1.41) | 21 | ⚠️ 可用但更贵 |
| PDH `\Processor(_Total)` ×4 | collect | 0.55 ms (p95 1.71) | — | ⚠️ 仅在需要 kernel/DPC/interrupt 时用 |
| **内存组成** | `NtQSI(2)` 344 字节 | **0.003 ms** | — | ✅ **碾压 PDH，一次拿全部** |
| 内存备用列表 | `NtQSI(80)` 176 字节 | **0.000 ms** | — | ✅ 拿按优先级的 standby |
| PDH `\Memory\*` ×7 | collect | 0.18 ms | — | ⚠️ 可用作交叉验证 |
| **CPU 频率** | `CallNtPowerInformation(11)` | **0.001 ms** | 20 | ✅ 极便宜 |

| CPU 基准频率 | 注册表 `~MHz` | ~0 | — | ✅ 本机 2993 MHz |
| **磁盘（总）** | PDH `\PhysicalDisk(*)` ×4 | **0.31 ms** (p95 0.49) | **3** | ✅ 便宜 |
| **网络** | PDH `\Network Interface(*)` ×2 | **2.17 ms** (p95 3.35) | **2** | ⚠️ 最贵的性能页项，仍可接受 |

### 8.2 性能页 1 Hz 预算核算

```
NtQSI(8)  每核 CPU          0.10 ms
NtQSI(2)  内存组成           0.00 ms
NtQSI(80) 内存备用列表       0.00 ms
NtQSI(3)  正常运行时间       0.00 ms
CallNtPowerInformation(11)  0.00 ms
PDH \Processor(_Total) ×4   0.55 ms
PDH \PhysicalDisk(*) ×4     0.31 ms
PDH \Network Interface(*)×2 2.17 ms
PDH \GPU Engine(*)          1.41 ms
PDH \GPU Adapter Memory(*)  0.06 ms
────────────────────────────────────
合计                        4.60 ms  =  1 Hz 预算的 0.46%
```

**结论：性能页全部数据源合计 4.6 ms，远低于进程页快照的 9 ms。**
放在独立后台线程、1 Hz 刷新完全可行。

### 8.3 关键实现细节

**(a) `NtQSI(8)` 必须给精确大小**
```
20 核 × 48 字节 = 960 字节
给 64KB 大缓冲反而返回 0xC0000004 (STATUS_INFO_LENGTH_MISMATCH)
```
实测：`need=960`，给 64KB → `status=0xC0000004 need=960`。

**(b) `NtQSI(2)` 必须给完整 344 字节**
216 字节 → `0xC0000004 need=344`。完整结构见 `tools/memprobe.cpp`。
关键字段偏移（已本机验证一致）：
```
+44  AvailablePages        ULONG   可用页数
+48  CommittedPages        ULONG   已提交页数
+52  CommitLimit           ULONG   提交限制
+112 PagedPoolPages        ULONG   分页缓冲池页数
+116 NonPagedPoolPages     ULONG   非分页缓冲池页数
+164 ResidentSystemCachePage ULONG 系统缓存驻留页数
```
用 `SIZE_T * 4096` 换算字节。

**(c) `NtQSI(80)` 给 176 字节**
```
+0   ZeroPageCount
+8   FreePageCount
+16  ModifiedPageCount
+24  ModifiedNoWritePageCount
+32  BadPageCount
+40  PageCountByPriority[8]       ← 备用内存按优先级，各 8 字节
+104 RepurposedPagesByPriority[8]
+168 ModifiedPageCountPageFile
```

**(d) PDH 通配符阵列读法 —— 必须严格三步**
```
1. PdhCollectQueryData(q)                         ← 采集
2. PdhGetFormattedCounterArrayW(c, FMT, &sz, &cnt, nullptr)
   → 返回 PDH_MORE_DATA，sz 是所需字节数        ← 只问大小，不填数据
3. PdhGetFormattedCounterArrayW(c, FMT, &sz, &cnt, items)
   → 返回 ERROR_SUCCESS，items 填好              ← 真正读数据
中间绝对不能再次 PdhCollectQueryData，否则第 2 步的 sz 失效。
```
这是本机实测踩到的坑：先调用第 2 步拿到 `sz` 后，如果中间又 collect 一次，
再传 `items` 会返回空。`docs/evidence/wildtest_out.txt` 有正确模式的完整输出。

**(e) 实测实例数（供 UI 布局参考）**
```
PhysicalDisk(*)      3 个   （0 C: / 1 D: / _Total）
Processor(*)        21 个   （20 核 + _Total）
Process(*)         530 个
GPU Engine(*)      623 个   （每个进程 × 每个引擎 × 每个物理适配器）
Network Interface(*) 2 个   （Realtek 有线 / TP-LINK 无线）
GPU Adapter Memory(*) 2 个
```
GPU 实例名格式：
```
pid_11092_luid_0x00000000_0x000146EC_phys_0_eng_0_engtype_3D
```
要拿"某进程的 GPU 利用率"，需按 `pid_(\d+)_` 提取 PID 后**求和**所有引擎。

**(f) CPU 频率在本机恒定**
```
CallNtPowerInformation(11) 返回：
  core0: Max=3001 Current=3001 Limit=3001 MaxIdle=2 CurIdle=2
  所有 20 核 CurrentMhz 一致：YES
```
服务器级 CPU 无 Turbo，平衡电源计划下也恒定 3001 MHz。所以"速度"栏在这里
永远显示 `3.00 GHz`，不要指望它变化。

**(g) 每核利用率计算（已验证）**
```
delta_idle   = cur.IdleTime   - prev.IdleTime
delta_kernel = cur.KernelTime - prev.KernelTime
delta_user   = cur.UserTime   - prev.UserTime
total = delta_kernel + delta_user        // kernel 已含 idle
util  = (1 - delta_idle / total) * 100
```
本机实测输出示例：`CPU 0: 43.8% (kernel=8750000 user=1250000 idle=5625000)`。
注意 `KernelTime` 包含 `IdleTime`，不能再相加。

## 9. 绘制实现建议

### 9.1 曲线

- **用 `Polyline`**，不用 `PolyBezier`（数据是离散采样点，贝塞尔会失真）
- 60 点环形缓冲：`double hist[60]; int head; int count;`
  ```
  hist[head] = value;
  head = (head + 1) % 60;
  if (count < 60) ++count;
  // 遍历：for (i=0; i<count; ++i) { idx = (head - count + i + 120) % 60; ... }
  ```
- 填充：`Polygon` 加两个底角点，用 `#0078D7` 与白按 alpha 0.25 混合的浅蓝
- 网格线：10 条 `MoveToEx/LineTo`，各自 1px

### 9.2 双缓冲

必须。整页（图表 + 20 个格子 + 统计文字）预估 3–6 ms，双缓冲避免闪烁。
复用现有的 `EnsureBackBuffer` 模式。

### 9.3 刷新策略

- 数据采集：独立线程，1 Hz
- 只在有新数据时 `InvalidateRect`（用代际号比对，已有实现可复用）
- 逻辑处理器格子：只在有所变化时重绘对应格子（可选优化，20 个格子全画也不慢）

### 9.4 每帧耗时预估

| 部分 | 预估 |
|---|---|
| 主图曲线（60 点 Polyline + 填充 + 10 条网格） | 0.3–0.8 ms |
| 20 个逻辑处理器格子（背景 + 2 行文字） | 1.5–3.0 ms |
| 统计文字（约 20 行） | 0.5–1.0 ms |
| 左侧列表（8 项 × 图标 + 2 行文字） | 0.5–1.0 ms |
| **合计** | **约 3–6 ms** |

在 16.6 ms 帧预算内，且只在数据更新时重绘（1 Hz），完全无压力。

## 10. 与进程页、详细信息页的数据源复用

性能页可以复用现有的 `Collector` 快照（进程/线程/句柄总数、totalPhysical、
availablePhysical 都已在内），只需新增：

1. `NtQSI(8)` 每核时间 → 新增一个小函数 `CollectPerCpu()`
2. `NtQSI(2)` 内存组成 → `CollectMemInfo()`
3. `NtQSI(80)` 备用列表 → `CollectMemLists()`
4. `CallNtPowerInformation(11)` 频率 → 一次性读 + 每 5 秒刷新
5. PDH 三个 query（处理器/磁盘/网络/GPU）→ 各自的 `PerfSet` 结构

建议做成一个 `PerfCollector` 类，独立线程，与现有 `Collector` 并行。
两者互不依赖：进程页要 450 条记录，性能页只要 20+3+2+600 个数。

## 11. 已知风险与不做的事

| 项 | 说明 |
|---|---|
| **每进程磁盘列** | `\Process(*)\IO Read Bytes/sec` 实测 **18.75 ms / 533 实例**。进程页的磁盘列如果要精确，不能每帧拉；建议改为从快照的 `ReadTransferCount` / `WriteTransferCount` 差分（快照自带，成本 0） |
| **每进程网络列** | Windows **不存在** per-process 网络 PDH 计数器。任务管理器自己是订阅 ETW `Microsoft-Windows-Kernel-Network`。第一版建议留空 |
| **每进程 GPU 列** | `\GPU Engine(*)` 623 实例，按 pid 聚合可行但成本 1.4 ms。建议 2–5 秒一次，不要 1 Hz |
| **NUMA 节点视图** | 本机单路单 NUMA，只有 1 个节点。实现上要支持 N 节点，但本机只能测到 1 |
| **GPU 多个引擎视图** | 需要解析 `engtype_3D` / `Copy` / `VideoDecode` 等，本机 discrete GPU 有多个引擎类型 |
| **"打开资源监视器"按钮** | 需要 `CreateProcess` 启动 `resmon.exe`（MUI 里有 `%systemroot%\system32\resmon.exe`） |
| 未实测的项 | 逻辑处理器格子的精确尺寸（随窗口自适应）、内存组成条各段的精确宽度比例、选项卡的精确高度（32px 是观察值） |
