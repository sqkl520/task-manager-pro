### 0.2 关于 `resstr(N)` 的关键规则（**其他 agent 必须知道**）

UIFILE 里的 `resstr(N)` **不是** STRINGTABLE id `N`，而是 **id = N+1**。
验证：UIFILE 共引用 159 个 resstr，其中 **32 个只有 `N+1` 存在、`N` 不存在**，且对照语义
全部吻合（例：`resstr(33803)` → 33804「内存组合图表」；`resstr(34460)` → 34461「磁盘传输速率」）。

## 2. 列描述表（.rdata / .data 里的出厂默认列配置）

这是本轮最重要的新发现：**8 张 56 字节步长的列表**，每张前面有 0x20 字节表头。

```
表头 (0x20B): +0x08 = 类型名指针("TmColFriendlyName")
              +0x0c = 页索引
              +0x10 = 列数
              +0x1c = 友好名指针
记录 (56B):   +0x00 = 恒为 1（用途未知，不是可见性）
              +0x10 = 列宽
              +0x18 = colId（列名 = STRINGTABLE[colId + 1]）
              +0x2c = 组索引
```

> ⚠ 上一轮 `_SUMMARY.md` 用的 `width@+0、colId@+8` 布局是**错的**（那会把指针误读成宽度）。
> 正确布局已由 8 张表 × 全部记录 100% 名字命中验证（0 条未命中）。

### 2.0 两条贯穿全表的编号规律（**必须先记这两条**）

**规律 A：`colId = STRINGTABLE 字符串 ID − 1`**

记录里的 `colId` 字段本身**不是**字符串 ID，加 1 才是。实测 100 列 100% 成立：

| 页面 | colId | → 字符串 ID | 列名 |

#### 2.2.1 掩码的置信度说明（**必须读**）

- 掩码值 `0x209D` 是磁盘上的**真实常量**（`.rdata` 文件偏移 `0xf3ed0`，与 `_SUMMARY.md` 记录一致）
- 掩码后面的 48 个 u32 确实是一组**列宽**（`0xf3ed8` 起，值域 35..200，与列宽语义吻合）
- 但它与 48 列表里的宽度**有 26/48 项不同**（如掩码后第一个是 100，表里「名称」是 145）
  → 说明这**不是同一份数据的两处副本**，而是**另一套（编译期默认/另一 DPI 档）列宽**
- 掩码本身置位 6 位（0,2,3,4,7,13），与「详细信息页默认 6 列」的页面实测**一致**，
  且这 6 个池索引对应的列名（名称/PID/状态/用户名/CPU/内存）与 `_SUMMARY.md` 的结论一致

**结论**：`0x209D` 作为「详细信息页默认可见掩码」这一用法**可用**（三重吻合），
但紧跟它的那 48 个宽度**不要**当作列宽 —— 列宽请用 §2.2 的表（来自 `0xf4318` 那张表）。
（`+0x00` 字段在 48 条记录里也是全 1，与进程页表一样不是可见性标志。）

## 8. 格式串专章

共 **109 条**含占位符的 STRINGTABLE 串（另有 22 条只含字面 `%` 而无占位符，如 `0%`、`100%`）。
机器可读版见 `O_strings.json` → `formatStrings[]`（带 `domain` 字段标注它属于哪个页面哪个字段）。

### 8.1 两种格式体系——**不混用，泾渭分明**

| 体系 | 条数 | 样例 | 谁在用 |
|---|---|---|---|
| **C printf** | **75** | `%0.1f MB %s`、`%.0f%%`、`%I64d MB 可用`、`%u MHz` | 应用代码 `swprintf` / `StringCchPrintf` 自己格式化 |
| **DUI 编号插值** | **34** | `%1!s!`、`%2!d!`、`%3!hu!`、`%1!d!%2!s!` | DUI/UIFILE 引擎做占位替换 |

实测统计：**printf 与 DUI 同时出现的串 = 0 条**。所以：
- 看到 `%I64d`/`%.0f`/`%0.1f`/`%s` → 应用层 printf
- 看到 `%1!`/`%2!` → UIFILE 层的绑定槽

**推论（对我们实现数值显示非常关键）**：
`%1!d!%2!s!` 这种两段式说明**数字和单位是分开两次取值的**：
`%1!d!` 是一个整数，`%2!s!` 是另一个字符串槽（单位串，如 `37036 %s%%` 的 `%`，
或 `32876` 的 `bps`）。`34292 %1!d!%2!s! (%3!d!%4!s!)` 更是**两对「数字+单位」**。
所以我方 `swprintf_s(buf, L"%.0f%%", pct)` 输出等价，但
`FmtMemText` 那种 `L"%.1f MB"` 把单位写死在格式串里的做法**不符合原版结构** ——
原版单位来自 `32876-32884`（`bps/Kbps/Mbps/Gbps/字节/秒/KB/秒/MB/秒/GB/秒`）和 `34470-34478`。

### 8.2 托盘 / 性能提示（16 条 `%I64d`）

| ID | 格式串 | 占位符 | 单位 |
|---|---|---|---|
