## 20 核的网格行列规则

**列数 = ceil(sqrt(n))，行数 = ceil(n / 列数)** → 20 核 = **5 列 × 4 行**。

推导：

- 原版 16 核（9700X，8C/16T）实测 4 列 × 4 行；`ceil(sqrt(16)) = 4`，完全吻合。
- 20 核：`ceil(sqrt(20)) = 5` → 5×4，最后一格空（20 正好整除，无空格）。
- 备选 `4 列 × 5 行` 也「能排满」，但它不是 sqrt 规则的自然结果；且原版 16 核不是 8×2 或 2×8，说明原版既不是「列数优先」也不是「行数优先」，而是接近正方形的 n 等分。sqrt 是唯一能同时复现 16→4×4 的简单规则。
- 兜底：`availW / cols < 60` 时递减列数（窗口被压窄不至于格子变一条线）。

实测下 20 核的预期几何（我方 1086 宽窗口）：可用宽约 834，`cellW = (834 - 5*4)/5 = 162`；
`chart` 高 `statsTop-10`，4 行约 70/格。宽高比 2.3:1，原版 241×94 是 2.56:1，接近。

## 没改的 / 风险

1. **大图纵向网格（50px）是推断，不是实测**。
   只有内存页有真原版大图参考。CPU「总体利用率」、磁盘、网络、GPU 四页的大图在原版里
   没有任何一张参考图 → 是否有竖线、间距多少**未知**。我按「同一套 CHARTV 绘制代码」推断
   所有大图一致（内存页实测 50px）。如果后续拿到其他页原版截图发现没有竖线，删掉
   `kGridStepX/kGridPhaseX` 那个循环即可（4 行）。**这是本次最大的一处推断**。
2. **横向 31px 同样只在内存页实测过**。CPU 逻辑核格子内是「10 带 / 6 带」的**比例**网格
   （94px 高 → 9px 间距），与大图的固定 31px 不是一套；本实现保持两套：格子按比例、
   大图按固定 31px。若原版 CPU 大图其实也是比例，需要再改。
3. **内存页图表高度 310 会在矮窗口被 `rc.bottom-90` 截断**：窗口高 < 约 500 时图表会变矮，
   网格线随之减少。这是保留的既有下限，未动。
4. **CPU 页网格视图下不再有切换按钮**，切回「总体利用率」只能走右键菜单
   「将图形更改为▸」(MENU 30206)。原版即如此；但若产品上希望保留按钮，需要回退 `perfpage.cpp:1315`。
5. **左上小标题**原版是「60 秒内的利用率 %」（实测 bbox x=240..334, y=100..146，两行），
   我方代码里已有该文案但画在 `chart.top-16`（一行），位置/换行方式不同 —— 未改，
   属排版项，不在本次两项任务内。
6. **内存页右侧属性列 8 项**（插槽/外形规格/硬件保留/最大内存）仍缺，需要采集层字段，
   不在本次范围。
7. 本文件同时被其它 agent 改过（`chart_` 默认值、`kGrid*` 常量在我接手时已部分存在）。
   我在其基础上补齐并统一，未回退任何他人改动；两文件括号/圆括号配平自检通过（0/0）。
